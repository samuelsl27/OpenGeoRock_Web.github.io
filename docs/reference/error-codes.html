5.5

Error codes

Describes OGR Slip2D 0.1.235

When OGR Slip2D cannot give a factor of safety, it says why, in a form a program can read as well as a person. This page lists the four negative codes written in place of the factor of safety of a rejected surface, the failure reasons behind them, the verdicts of the admissibility checks, the errors of the operations layer and the MCP server, and the exit codes of the command-line programs.

5.5.1Surface error codes#

A surface that has no admissible factor of safety keeps its place among the results, and a negative code is written where its factor would be. How the checks behind −120 and −112 work is explained in Section 3.3.

One function gives the code of every rejected evaluation, in this order:

  1. a valid surface that passed the checks has no code;
  2. rejected by the Tensile Stress Check: −120 (tension is tested first, so a surface failing both checks is a tensile rejection);
  3. the checks themselves could not be evaluated: −101;
  4. rejected by the m-alpha check: −112;
  5. no converged factor: −111;
  6. anything else: −101.

Because −111 covers every calculation that produced no converged factor, it is not only a convergence problem: circles whose mass does not slide (zero_driving) and, in a rapid-drawdown analysis, candidates to which the procedure does not apply (drawdown_not_applicable) are −111 too, and the reason tells them apart. A surface rejected before it could be sliced has no result, no code and no row; the census counts it as not sliced.

The codes appear in the Interpret window (Data → Export Raw Data…, whose last column holds the factor of safety or the code; Data → Summary of Invalid Surfaces…; Query → Query Invalid Surfaces, which shows the code of grid centres with no valid surface; and the Surfaces with error code option of the surface filter), and in the MCP tool results_query (views error_codes, invalid_summary, raw_data and filter). The HDF5 results file stores no code: a surface without a factor has no fos attribute and carries its reason (Section 5.4.5).

In OGR Slip2D

The four codes are the constants ERROR_TENSILE, ERROR_M_ALPHA, ERROR_NOT_CONVERGED and ERROR_OTHER, and error_code() is the single mapping used by the raw-data export, the census of the Interpret window and the MCP server.

Source: ogr_slip2d/interpretation.py

5.5.2Failure reasons#

An evaluation that produced no factor of safety has fos = None (never NaN), an error_message written for a person and a reason written for a program: one of the strings below, so that a run can be summarised as "this reason, so many surfaces" without parsing prose. The reason is the reason attribute of a surface in the HDF5 results file and the reason key of a surface in the answers of the operations layer and the MCP server.

In OGR Slip2D

The reasons are the REASON_* constants, and ALL_REASONS is the set every method's reason must belong to, so that a new reason cannot be born as a loose string. They are deliberately not translated: the interface translates the message where it shows it.

Source: ogr_slip2d/methods/base.py

5.5.3Admissibility checks#

A surface that fails an admissibility check has not failed to compute: its factor converged and is kept, because the searches that steer by the factor of safety need it, but the surface is judged inadmissible afterwards and is never reported as the critical one, unless every valid surface is inadmissible, in which case the checks are ignored and the result says so. Both checks are set in Analysis → Project Settings → Advanced (Tensile stress check with its Percentage of slices, and Check m-alpha < 0.2).

5.5.4Errors of the operations layer and the MCP server#

An operation of ogr_api that fails on purpose raises an OgrApiError with a stable code, a message, a hint where there is one and, sometimes, details. An MCP client receives it as [E_CODE] message Hint: hint; a Python script catches it and reads code, message, hint and details. The codes are stable; the wording of the messages is not. An unknown name always comes with the closest known names (Did you mean …?).

An exception that is not an OgrApiError reaches an MCP client as its type and message, without a code. Over HTTP, the server itself answers 401 to a missing or wrong bearer token, 421 to a Host that is not its own and 403 to a foreign Origin (Section 5.1.11).

In OGR Slip2D

The reader of these messages is very often a language model, and what lets it recover is being told what was wrong and what to do instead; hence the hint, and the suggestions for every unknown name.

Source: ogr_api/errors.py · ogr_api/workspace.py · ogr_gui/agent_bridge.py
