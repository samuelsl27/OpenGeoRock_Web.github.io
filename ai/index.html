Slope stability your AI agent can drive.

OGR Slip2D ships an official Model Context Protocol server, developed in the same repository as the solver. An agent can open the program, build the model, run the analysis, read every slice and look at a picture of the result — on your machine, in the window you are looking at.

Install the MCP server → Tool reference
Where it stands

One of the first geotechnical programs with an official MCP server — and, to our knowledge (October 2026), the first open-source slope-stability program to ship one. It works with any MCP client, including local models that never leave your computer.

Server since OGR Slip2D 0.1.195 · window bridge since 0.1.207

§ 01 — The idea

An engineer's tools, within an agent's reach.

The Model Context Protocol is an open standard for connecting language-model applications to programs. OGR Slip2D publishes its operations as MCP tools, so any compatible client can use them — and you keep the engineering judgement.

Build

A whole model in one call

Geometry, materials, the region each material occupies and the water table, from a description — or from a DXF drawing. Every edit is one undo step.

Compute

The same engine you use

Limit equilibrium with any of the nine methods and seven searches, finite-element groundwater, probabilistic runs, back analysis and optimisation, in background jobs that can be cancelled.

Read

Numbers and pictures

Critical surfaces with their slices, the questions of the interpretation window, error codes, groundwater fields — and a PNG of the model, or of the real canvas, that the agent can look at.

§ 02 — A real session

From a sentence to a factor of safety.

This exchange is the one that produced the slope on the home page. The agent made five calls, the first to server_info; the program did the engineering.

  • model_define built the 16 m slope: three materials, two contacts and a water table assigned to all three.
  • analysis_configure chose the methods, the grid search, 30 slices and the direction of failure.
  • analysis_run evaluated 1 859 circles per method in a background job.
  • results_get returned the critical surfaces with their slice tables.

Critical factors of safety: Bishop 1.300, Spencer 1.290 (λ = 0.343) and Morgenstern–Price 1.292, all on the same circle — centre (60.0, 47.6), radius 31.2 m. It runs through the clay, below the water table for most of its length, and exits 3.8 m beyond the toe.
Which slice carries the highest pore pressure?
The slices under the bench, around x = 48–50 m: about 48.6 kPa at their base. Above the water table, towards both ends of the circle, the pore pressure is zero.
§ 03 — Installation

Connect your agent in three steps.

You need Python 3.11 or newer and an MCP client. The server is part of OGR Slip2D: there is nothing else to download. Replace C:\path\to\projects with the folder where your .ogr models live.

  1. Install OGR Slip2D with the MCP extra

    The [mcp] extra adds the official MCP SDK for Python (MIT licence). The desktop program does not need it; the server does.

    git clone https://github.com/samuelsl27/OGR-Slip2D.git
cd OGR-Slip2D
python -m venv .venv
.venv\Scripts\activate          # macOS / Linux: source .venv/bin/activate
pip install -e ".[mcp]"
ogr-slip2d-mcp --version

    If ogr-slip2d-mcp is not on the client's PATH, use the full path of the executable, or run python -m ogr_mcp, which does exactly the same.

  2. Register the server in your client

    Edit claude_desktop_config.json — %APPDATA%\Claude\ on Windows, ~/Library/Application Support/Claude/ on macOS. The Microsoft Store version keeps it in %LOCALAPPDATA%\Packages\Claude_<id>\LocalCache\Roaming\Claude\. Then restart Claude.

    {
  "mcpServers": {
    "ogr-slip2d": {
      "command": "ogr-slip2d-mcp",
      "args": ["--workdir", "C:\\path\\to\\projects"]
    }
  }
}

    If Claude cannot find the command, put the full path of ogr-slip2d-mcp.exe (inside your virtual environment's Scripts folder) in command.

    One command registers the server for Claude Code:

    claude mcp add ogr-slip2d -- ogr-slip2d-mcp --workdir "C:\path\to\projects"

    Claude Code asks for confirmation before each tool call. Keep it that way for python_exec (see Security).

    Local models in LM Studio read %USERPROFILE%\.lmstudio\mcp.json on Windows or ~/.lmstudio/mcp.json on macOS and Linux:

    {
  "mcpServers": {
    "ogr-slip2d": {
      "command": "ogr-slip2d-mcp",
      "args": ["--profile", "compact", "--workdir", "C:\\path\\to\\projects"]
    }
  }
}

    Use --profile compact with small models. It publishes 14 tools instead of 74: model_define builds the geometry in one call and python_exec covers the rest. A small model gets lost among many tools, and every tool description takes context on every request.

    Ollama serves models but does not speak MCP itself: the client that uses the model does. With mcp-client-for-ollama, or any MCP client that accepts the mcpServers format, the entry is the same as for LM Studio:

    {
  "mcpServers": {
    "ogr-slip2d": {
      "command": "ogr-slip2d-mcp",
      "args": ["--profile", "compact", "--workdir", "C:\\path\\to\\projects"]
    }
  }
}

    Open WebUI connects to MCP servers over HTTP only (Streamable HTTP, Open WebUI 0.6.31 or newer). Start the server with a token:

    ogr-slip2d-mcp --transport http --port 8765 --token-file token.txt --workdir "C:\path\to\projects"

    Then, in Open WebUI: Settings → Admin → Integrations → External Tool Servers → + Add Connection. Type MCP (Streamable HTTP), URL http://127.0.0.1:8765/mcp, authentication Bearer with the token as key.

    Without --token-file or OGR_MCP_TOKEN, the server generates a token and prints it when it starts. If Open WebUI runs in Docker, use http://host.docker.internal:8765/mcp and start the server with --host 0.0.0.0 and an explicit token — without one it refuses to start.

    Read this first

    ChatGPT only connects to public HTTPS servers through OAuth. Exposing the server to the Internet exposes python_exec — that is, your machine. Do it only when you need it, and stop the tunnel when you finish.

    1. Start the server on loopback with a token of at least 32 characters, and the public address of your tunnel:

    ogr-slip2d-mcp --transport http --port 8765 --token-file token.txt --public-url https://YOUR-TUNNEL.example --workdir "C:\path\to\projects"

    2. Put a tunnel that terminates HTTPS in front of http://127.0.0.1:8765 — for example cloudflared tunnel --url http://127.0.0.1:8765 gives you the address for --public-url (restart the server with it).

    3. In ChatGPT, enable developer mode and create a connector with the address https://YOUR-TUNNEL.example/mcp and OAuth authentication.

    4. ChatGPT sends you to the server's /approve page: check that the client is the one you expect and type the token from token.txt. The server acts as its own OAuth 2.1 authorisation server (PKCE, dynamic registration); access tokens last one hour and live only in memory.

    With the OpenAI Agents SDK for Python, the server is a stdio MCP server:

    from agents import Agent, Runner
from agents.mcp import MCPServerStdio

async with MCPServerStdio(
    params={"command": "ogr-slip2d-mcp",
            "args": ["--workdir", r"C:\path\to\projects"]},
    client_session_timeout_seconds=60,   # an analysis can take a while
) as ogr:
    agent = Agent(name="geotechnics", mcp_servers=[ogr],
                  instructions="Analyse slopes with OGR Slip2D.")
    result = await Runner.run(agent, "Build and analyse the slope ...")

    client_session_timeout_seconds matters: the SDK's default is a few seconds, and analysis_run waits up to 30 s by default before returning a job to poll with job_get.

    Clients that integrate tools through OpenAPI (for example BionicGPT) can use mcpo, which turns an MCP server into an OpenAPI service. Install it in its own environment, pinned to the 1.x MCP SDK it was built for:

    python -m venv mcpo-env
mcpo-env\Scripts\pip install mcpo "mcp<2"
mcpo-env\Scripts\mcpo --port 8000 --api-key "your-key" -- ogr-slip2d-mcp --workdir "C:\path\to\projects"

    The specification is then at http://localhost:8000/openapi.json and interactive docs at /docs. model_render returns a data URI; pass save_path to also get the PNG on disk.

  3. Check the connection

    Ask the agent to call server_info. It answers with the version, the units (SI) and the published tools — and says whether the next call goes to an open OGR Slip2D window or to a model of its own.

    {"server": "ogr-slip2d", "units": "SI: m, kN, kPa, kN/m3, degrees", "profile": "full",
 "attached_to_window": {"window_open": true, "next_call_goes_to": "the open window"},
 "program_coverage": {"mapped": 116, "pending": 0}, "licence": "AGPL-3.0-or-later", …}
§ 04 — Same window, same model

You watch. You can undo.

If OGR Slip2D is open, whatever you ask the agent happens in its window — from any client, in any order of opening. Nothing to configure: the program starts its bridge when it opens.

  • Each edit of the agent is one step of Edit → Undo, and the canvas redraws.
  • An analysis run by the agent appears in the results panel and on the canvas, like Compute.
  • project_new and project_open refuse while there are unsaved changes: the agent cannot throw your work away.
  • The bridge listens on 127.0.0.1 only, with a fresh random token every time. Turn it off in Tools → Agent bridge (MCP) or start the program with --no-agent-bridge.

§ 06 — Security

Powerful by design. Local by default.

The server always publishes python_exec, which runs Python with your user's permissions — it covers whatever has no tool yet. Whoever can talk to the server can run code on your machine, so the defaults keep it to you.

  • stdio (Claude, LM Studio, the Agents SDK): the server is a child process of the client and opens no port. The remaining risk is prompt injection; keep the client's confirmation before each tool call.
  • HTTP: always with a token, also on 127.0.0.1, compared in constant time; Host and Origin are checked against DNS rebinding. Without a token there is no network access.
  • Internet (--public-url): OAuth 2.1 with PKCE, rate-limited approval, tokens in memory only. The server never opens tunnels itself.
  • No telemetry: the server makes no network calls of its own.
§ 07 — Try asking

Prompts that work.

Give the agent the engineering inputs — geometry, strengths, water — and ask for checks you would make yourself. Units are SI throughout.

Model

“Open dam.dxf, tell me which layers you would import as external and material boundaries, and import them.”

Compare

“Run Bishop, Spencer and Morgenstern–Price with a grid search and tell me whether they agree on the critical circle.”

Groundwater

“Mesh the dam, put the reservoir at 17 m, solve the steady seepage and use that pore pressure in the downstream slope.”

Probabilistic

“Make c′ and φ′ of the clay normal with a 15 % and 8 % coefficient of variation, correlated −0.5, and give me the probability of failure.”

Design

“Which horizontal support force at elevation 4 m brings the critical factor of safety to 1.3?”

Report

“Save the model, export the critical surfaces to DXF and generate the PDF report of the last analysis.”

§ 08 — Questions

Frequently asked

Does my model leave my computer?

The server makes no network calls. What reaches a model provider is what your client sends to it — the same as any conversation. With a local model (LM Studio, Ollama), nothing leaves your machine.

Which models can use it?

Any client that speaks MCP. Large hosted models handle the full 74-tool profile well; for small local models, start the server with --profile compact.

Can the agent break my model?

Every edit is an undo step, a script run with python_exec is one step and is rolled back if it fails, and the agent cannot open or create a model over unsaved changes. Settings that a calculation would not read are refused with the reason, instead of being stored.

Is the agent's answer an engineering result?

The numbers come from the same engine as the desktop program, and they deserve the same checks: independent calculations, sensitivity to the inputs, engineering judgement. A design is signed by an engineer, not by a program — and not by an agent.
