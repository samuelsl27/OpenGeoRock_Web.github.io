Inicio/IA y MCP

Análisis de taludes que puede dirigir tu agente de IA.

OGR Slip2D incorpora un servidor oficial del Model Context Protocol, desarrollado en el mismo repositorio que el motor de cálculo. Un agente puede abrir el programa, construir el modelo, lanzar el cálculo, consultar cada dovela y ver una imagen del resultado, todo en tu equipo y en la misma ventana que tienes delante.

Instalar el servidor MCP → Referencia de herramientas
Situación actual

Uno de los primeros programas geotécnicos con servidor MCP oficial y, hasta donde sabemos (octubre de 2026), el primero de estabilidad de taludes de código abierto. Funciona con cualquier cliente MCP, incluidos los modelos locales, con los que nada sale de tu ordenador.

Servidor desde OGR Slip2D 0.1.195 · puente con la ventana desde la 0.1.207

§ 01 — La idea

Las herramientas de un ingeniero, al alcance de un agente.

El Model Context Protocol es un estándar abierto para conectar con otros programas las aplicaciones basadas en modelos de lenguaje. OGR Slip2D ofrece sus operaciones como herramientas MCP que cualquier cliente compatible puede usar, y el criterio de ingeniería sigue siendo tuyo.

Construir

Un modelo completo en una sola llamada

Geometría, materiales, la región que ocupa cada uno y el nivel freático, a partir de una descripción o de un plano DXF. Cada cambio es un paso que se puede deshacer.

Calcular

El mismo motor que usas tú

Equilibrio límite con cualquiera de los nueve métodos y las siete búsquedas, agua subterránea por elementos finitos, análisis probabilísticos, retroanálisis y optimización, en tareas en segundo plano que se pueden cancelar.

Leer

Números e imágenes

Superficies críticas con sus dovelas, las consultas de la ventana de interpretación, códigos de error, campos de agua subterránea y un PNG del modelo, o del área de dibujo tal como se ve, que el agente puede mirar.

§ 02 — Una sesión real

De una frase a un factor de seguridad.

De esta conversación salió el talud de la portada. El agente hizo cinco llamadas, la primera a server_info, y el trabajo de ingeniería lo hizo el programa.

  • model_define construyó el talud de 16 m: tres materiales, dos contactos y un nivel freático asignado a los tres.
  • analysis_configure eligió los métodos, la búsqueda por rejilla, 30 dovelas y la dirección de rotura.
  • analysis_run calculó 1 859 círculos con cada método en una tarea en segundo plano.
  • results_get devolvió las superficies críticas con sus tablas de dovelas.
  sesión con un agente · ogr-slip2d
Modela un talud de 16 m con una berma a media altura: arena limosa sobre arcilla y, debajo, grava densa; nivel freático a 6 m bajo la coronación. Compruébalo con Bishop, Spencer y Morgenstern-Price.

analysis_runtarea terminada · 87 s

Factores de seguridad críticos: Bishop 1.300, Spencer 1.290 (λ = 0.343) y Morgenstern-Price 1.292, los tres en el mismo círculo, de centro (60.0, 47.6) y radio 31.2 m. Atraviesa la arcilla, va por debajo del nivel freático en la mayor parte de su recorrido y sale 3.8 m más allá del pie.
¿En qué dovela es mayor la presión intersticial?
En las dovelas que quedan bajo la berma, hacia x = 48–50 m, con unos 48.6 kPa en la base. Hacia los dos extremos del círculo, por encima del nivel freático, la presión intersticial es nula.
§ 03 — Instalación

Conecta tu agente en tres pasos.

Necesitas Python 3.11 o posterior y un cliente MCP. El servidor forma parte de OGR Slip2D: no hay que descargar nada más. Sustituye C:\path\to\projects por la carpeta donde guardas tus modelos .ogr.

  1. Instala OGR Slip2D con el extra MCP

    El extra [mcp] añade el SDK oficial de MCP para Python (licencia MIT). El programa de escritorio no lo necesita; el servidor, sí.

    git clone https://github.com/samuelsl27/OGR-Slip2D.git
cd OGR-Slip2D
python -m venv .venv
.venv\Scripts\activate          # macOS / Linux: source .venv/bin/activate
pip install -e ".[mcp]"
ogr-slip2d-mcp --version

    Si ogr-slip2d-mcp no está en el PATH del cliente, usa la ruta completa del ejecutable o ejecuta python -m ogr_mcp, que hace exactamente lo mismo.

  2. Registra el servidor en tu cliente

    Edita claude_desktop_config.json, que está en %APPDATA%\Claude\ en Windows y en ~/Library/Application Support/Claude/ en macOS. La versión de Microsoft Store lo guarda en %LOCALAPPDATA%\Packages\Claude_<id>\LocalCache\Roaming\Claude\. Después, reinicia Claude.

    {
  "mcpServers": {
    "ogr-slip2d": {
      "command": "ogr-slip2d-mcp",
      "args": ["--workdir", "C:\\path\\to\\projects"]
    }
  }
}

    Si Claude no encuentra el comando, escribe en command la ruta completa de ogr-slip2d-mcp.exe (dentro de la carpeta Scripts de tu entorno virtual).

    Un solo comando registra el servidor en Claude Code:

    claude mcp add ogr-slip2d -- ogr-slip2d-mcp --workdir "C:\path\to\projects"

    Claude Code pide confirmación antes de usar cada herramienta. No la desactives para python_exec (ver Seguridad).

    Para los modelos locales de LM Studio, la configuración está en %USERPROFILE%\.lmstudio\mcp.json en Windows o en ~/.lmstudio/mcp.json en macOS y Linux:

    {
  "mcpServers": {
    "ogr-slip2d": {
      "command": "ogr-slip2d-mcp",
      "args": ["--profile", "compact", "--workdir", "C:\\path\\to\\projects"]
    }
  }
}

    Usa --profile compact con los modelos pequeños. Publica 14 herramientas en lugar de 74: model_define construye la geometría en una sola llamada y python_exec cubre el resto. Un modelo pequeño se pierde entre muchas herramientas, y la descripción de cada una ocupa contexto en todas las peticiones.

    Ollama sirve modelos, pero no habla MCP: eso lo hace el cliente que usa el modelo. Con mcp-client-for-ollama, o con cualquier cliente MCP que acepte el formato mcpServers, la entrada es la misma que en LM Studio:

    {
  "mcpServers": {
    "ogr-slip2d": {
      "command": "ogr-slip2d-mcp",
      "args": ["--profile", "compact", "--workdir", "C:\\path\\to\\projects"]
    }
  }
}

    Open WebUI solo se conecta a servidores MCP por HTTP (Streamable HTTP, Open WebUI 0.6.31 o posterior). Arranca el servidor con un token:

    ogr-slip2d-mcp --transport http --port 8765 --token-file token.txt --workdir "C:\path\to\projects"

    Después, en Open WebUI, ve a Settings → Admin → Integrations → External Tool Servers → + Add Connection y elige el tipo MCP (Streamable HTTP), la URL http://127.0.0.1:8765/mcp y la autenticación Bearer, con el token como clave.

    Sin --token-file ni OGR_MCP_TOKEN, el servidor genera un token y lo muestra al arrancar. Si Open WebUI se ejecuta en Docker, usa http://host.docker.internal:8765/mcp y arranca el servidor con --host 0.0.0.0 y un token explícito, porque sin él el servidor no arranca.

    Lee esto primero

    ChatGPT solo se conecta a servidores HTTPS públicos mediante OAuth. Si publicas el servidor en Internet, publicas también python_exec, es decir, tu equipo. Hazlo solo cuando lo necesites y cierra el túnel al terminar.

    1. Arranca el servidor en la interfaz local (loopback) con un token de al menos 32 caracteres y la dirección pública de tu túnel:

    ogr-slip2d-mcp --transport http --port 8765 --token-file token.txt --public-url https://YOUR-TUNNEL.example --workdir "C:\path\to\projects"

    2. Pon delante de http://127.0.0.1:8765 un túnel que termine la conexión HTTPS. Por ejemplo, cloudflared tunnel --url http://127.0.0.1:8765 te da la dirección para --public-url (reinicia el servidor con ella).

    3. En ChatGPT, activa el modo desarrollador y crea un conector con la dirección https://YOUR-TUNNEL.example/mcp y autenticación OAuth.

    4. ChatGPT te lleva a la página /approve del servidor: comprueba que el cliente es el que esperas y escribe el token de token.txt. El servidor hace de su propio servidor de autorización OAuth 2.1 (PKCE, registro dinámico), y los tokens de acceso duran una hora y solo se guardan en memoria.

    Con el Agents SDK de OpenAI para Python, el servidor se usa como servidor MCP por stdio:

    from agents import Agent, Runner
from agents.mcp import MCPServerStdio

async with MCPServerStdio(
    params={"command": "ogr-slip2d-mcp",
            "args": ["--workdir", r"C:\path\to\projects"]},
    client_session_timeout_seconds=60,   # an analysis can take a while
) as ogr:
    agent = Agent(name="geotechnics", mcp_servers=[ogr],
                  instructions="Analyse slopes with OGR Slip2D.")
    result = await Runner.run(agent, "Build and analyse the slope ...")

    client_session_timeout_seconds es importante: el SDK espera por defecto unos pocos segundos, y analysis_run espera hasta 30 s (su valor por defecto) antes de devolver una tarea cuyo estado se consulta con job_get.

    Los clientes que integran herramientas mediante OpenAPI (por ejemplo, BionicGPT) pueden usar mcpo, que convierte un servidor MCP en un servicio OpenAPI. Instálalo en un entorno aparte, con la versión 1.x del SDK de MCP, que es para la que está hecho:

    python -m venv mcpo-env
mcpo-env\Scripts\pip install mcpo "mcp<2"
mcpo-env\Scripts\mcpo --port 8000 --api-key "your-key" -- ogr-slip2d-mcp --workdir "C:\path\to\projects"

    La especificación queda entonces en http://localhost:8000/openapi.json y la documentación interactiva, en /docs. model_render devuelve la imagen como URI de datos; pasa save_path si quieres además el PNG en disco.

  3. Comprueba la conexión

    Pide al agente que llame a server_info. La respuesta incluye la versión, las unidades (SI) y las herramientas publicadas, y dice si la próxima llamada irá a una ventana abierta de OGR Slip2D o a un modelo propio del servidor.

    {"server": "ogr-slip2d", "units": "SI: m, kN, kPa, kN/m3, degrees", "profile": "full",
 "attached_to_window": {"window_open": true, "next_call_goes_to": "the open window"},
 "program_coverage": {"mapped": 116, "pending": 0}, "licence": "AGPL-3.0-or-later", …}
§ 04 — La misma ventana, el mismo modelo

Tú lo ves. Y puedes deshacerlo.

Si OGR Slip2D está abierto, lo que pidas al agente ocurre en su ventana, sea cual sea el cliente y abras primero lo que abras. No hay nada que configurar: el programa activa su puente al arrancar.

  • Cada cambio del agente es un paso de Edit → Undo, y el área de dibujo se actualiza al momento.
  • Un cálculo lanzado por el agente aparece en el panel de resultados y en el área de dibujo, igual que al pulsar Compute.
  • project_new y project_open no se ejecutan si hay cambios sin guardar: el agente no puede hacerte perder el trabajo.
  • El puente solo escucha en 127.0.0.1, con un token aleatorio nuevo cada vez. Puedes desactivarlo en Tools → Agent bridge (MCP) o arrancar el programa con --no-agent-bridge.

§ 06 — Seguridad

Potente a propósito. Local por defecto.

El servidor publica siempre python_exec, que ejecuta Python con los permisos de tu usuario y cubre todo lo que aún no tiene herramienta propia. Quien pueda comunicarse con el servidor puede ejecutar código en tu equipo; por eso, la configuración por defecto solo te deja acceder a ti.

  • stdio (Claude, LM Studio, el Agents SDK): el servidor es un proceso hijo del cliente y no abre ningún puerto. El riesgo que queda es la inyección de instrucciones (prompt injection), así que mantén activada la confirmación del cliente antes de cada herramienta.
  • HTTP: siempre con token, también en 127.0.0.1, y comparado en tiempo constante; las cabeceras Host y Origin se comprueban para evitar el DNS rebinding. Sin token no hay acceso por red.
  • Internet (--public-url): OAuth 2.1 con PKCE, aprobación con límite de frecuencia y tokens solo en memoria. El servidor nunca abre túneles por su cuenta.
  • Sin telemetría: el servidor no hace llamadas de red por su cuenta.
§ 07 — Prueba a pedir

Peticiones que funcionan.

Dale al agente los datos de ingeniería (geometría, resistencias, agua) y pídele las comprobaciones que harías tú. Todas las unidades son del SI.

Modelo

«Abre dam.dxf, dime qué capas importarías como contorno externo y como contornos de material, e impórtalas.»

Comparar

«Calcula el talud por Bishop, Spencer y Morgenstern-Price con búsqueda por rejilla y dime si los tres dan el mismo círculo crítico.»

Agua subterránea

«Genera la malla de la presa, pon el nivel del embalse a 17 m, calcula la filtración en régimen permanente y usa esas presiones intersticiales en el talud de aguas abajo.»

Probabilístico

«Trata c′ y φ′ de la arcilla como variables normales, con coeficientes de variación del 15 % y del 8 % y una correlación de −0.5, y dame la probabilidad de rotura.»

Diseño

«¿Qué fuerza horizontal de soporte hace falta a la cota 4 m para que el factor de seguridad crítico llegue a 1.3?»

Informe

«Guarda el modelo, exporta las superficies críticas a DXF y genera el informe en PDF del último análisis.»

§ 08 — Preguntas

Preguntas frecuentes

¿Mi modelo sale de mi ordenador?

El servidor no hace ninguna llamada de red. Al proveedor del modelo solo le llega lo que le envía tu cliente, como en cualquier otra conversación. Con un modelo local (LM Studio, Ollama), nada sale de tu equipo.

¿Qué modelos pueden usarlo?

Cualquier cliente que hable MCP. Los modelos grandes en la nube manejan bien el perfil completo de 74 herramientas; con modelos locales pequeños, arranca el servidor con --profile compact.

¿Puede el agente estropear mi modelo?

Cada cambio se puede deshacer; un script ejecutado con python_exec cuenta como un solo paso y se revierte si falla, y el agente no puede abrir ni crear un modelo si hay cambios sin guardar. Además, los ajustes que el cálculo no usaría se rechazan explicando el motivo, en lugar de guardarse.

¿La respuesta del agente es un resultado de ingeniería?

Las cifras salen del mismo motor de cálculo que las del programa de escritorio y merecen las mismas comprobaciones: cálculos independientes, análisis de sensibilidad y criterio de ingeniería. Un proyecto lo firma un ingeniero, no un programa; y tampoco un agente.
